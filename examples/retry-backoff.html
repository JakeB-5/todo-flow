Bounded retries for temporary failures

Recover from temporary request failures without retrying forever.

Scope

Retry utility and its unit tests. Permanent failures and UI copy are handled separately.

Problem and evidence

Repeated transient failures currently require callers to retry manually.

Make the failure path explicit

Retries and error presentation can be developed independently. Integration checks confirm that exhausted retries produce the intended user message.

Acceptance condition

IDExpected resultHow to verify
retryA transient failure can recover within the configured total attempt limit, including the first call; exhaustion stops at that limit.Source: the illustrative requirement in #retry-contract. With limit 3 and responses temporary, temporary, temporary, ok, expect exhausted after exactly 3 calls, never ok on call 4. tests/test_retry_behavior_example.py applies the same check to the wrong and corrected implementations and also checks success and a non-retryable response.

Independent expectation for condition retry

Source: this public example's illustrative selected requirement is that the attempt limit counts all calls, including the first call. This is a stated requirement, not a fact inferred from the implementation or a claim about production behavior. The executable example uses synthetic responses and no network or timing.
